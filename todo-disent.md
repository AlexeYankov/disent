# План улучшения проекта disent

## Цель

Сделать браузер стран устойчивым при прямом открытии URL, корректно работающим с SSR и кэшем React Query, типобезопасным, покрытым тестами и подготовленным к дальнейшей разработке.

## Приоритеты

- **P0** — исправить ошибки, влияющие на работоспособность приложения.
- **P1** — повысить надёжность, качество кода и пользовательский опыт.
- **P2** — улучшения, которые упрощают поддержку и развитие проекта.

## Этап 1. Данные, SSR и маршрутизация

### 1.1. Исправить SSR-гидрацию React Query [P0]

- [ ] Создать или использовать единый серверный `QueryClient` для префетча.
- [ ] Передать результат `dehydrate(queryClient)` в `HydrationBoundary` или существующий provider.
- [ ] Убедиться, что клиентский `useGetCountries` использует тот же query key и те же параметры.
- [ ] Удалить передачу пустого `{}` как `dehydratedState`.
- [ ] Проверить, что после SSR первый рендер не запускает лишний повторный запрос.

**Зависимости:** 0.1.

**Готово, когда:** HTML страницы содержит данные, а React Query использует префетчированный кэш после гидрации.

### 1.2. Убрать дублирование стран в Zustand и React Query [P0]

- [ ] Определить React Query единственным источником серверных данных о странах.
- [ ] Оставить в Zustand только UI-состояние, если оно действительно нужно.
- [ ] Удалить запись списка стран в Zustand и связанные неиспользуемые селекторы.
- [ ] Проверить, что переходы, обновление страницы и возврат назад используют query cache.

**Зависимости:** 1.1.

**Готово, когда:** один список стран не хранится параллельно в двух хранилищах.

### 1.3. Переделать загрузку страницы страны [P0]

- [ ] Не полагаться на то, что пользователь сначала посетил главную страницу.
- [ ] Обработать прямое открытие URL, обновление страницы и открытие ссылки в новой вкладке.

**Зависимости:** 1.1.

**Готово, когда:** detail page работает после прямого перехода без предварительной загрузки главной страницы.
